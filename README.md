# news.ai

Закрытый Telegram-канал «ИИ-сводка» (бот @newsai_egor_bot). Три раза в день — 09:07, 17:07 и 01:07 по
Бангкоку — облачная задача Claude Code собирает новое из фидов, сайтов, X и issue Claude Code, агент
отбирает важное и собирает выпуск: крупные новости по одной, затем списки сайтов, X, денег и сделок,
GitHub `скоро` и строка `не ответили`. Публикует выпуск не агент, а публикатор — workflow GitHub
Actions основной ветки.

Источники — `istochniki.json`: официальные каналы Anthropic, OpenAI и Google (Блог Google — три ленты
разделов: ИИ, модели Gemini, developers-tools; Google Developers Blog — лента и даты из карты сайта;
DeepMind), AINews, Simon Willison, Ben's Bites, Cursor, Techmeme, 30 аккаунтов X и issue Claude Code.
Каналы одной компании — один источник: у Google это Блог Google, Google Developers Blog и DeepMind.
X собирается бережно: аккаунты по одному с паузой 2 секунды, на 429 — ожидание `Retry-After` и один
повтор, 404 — повтор и проверка профиля («аккаунт не найден» отличается от сбоя), весь X — не дольше
5 минут; посты ответивших аккаунтов идут в выпуск, остальные — с причиной в отчёте сбора.

Только стандартная библиотека Python 3.11+. На Windows вместо `python3` — `py -3`.

## Как идёт выпуск

0. Файл issue `dannye/issue.json` — issue Claude Code с ответом команды для следующего выпуска. Нужен
   потому, что из облака Claude Code прокси GitHub отвечает 403 на всё, кроме репозитория задачи.
   Пишет его команда `sbor-issue` штатным токеном Actions с правом только на чтение, коммитит в
   основную ветку ключом развёртывания — так же, как состояние. Главный путь — публикатор после каждой
   своей заявки (шаг 3): не зависит от расписания GitHub. Запасной — сборщик issue: вручную — Actions →
   `sbor-issue` → Run workflow на основной ветке, и по расписанию в 08:40, 16:40, 00:40 по Бангкоку, за
   27 минут до агента (на 13.11 расписание GitHub в этом репозитории не сработало ни разу — ни у
   сборщика, ни у сторожа). Не прошёл ни тот, ни другой — в канал ничего, агент берёт прежний файл,
   пока он годен.
1. Агент облачной задачи в свежей копии основной ветки: `sbor` → отбор по инструкции
   `agent/SKILL.md` → самопроверка `proverit`. Issue `sbor` агента берёт из API, а если запрос не
   прошёл — из файла issue, когда тот годен: собран не раньше чем за 24 часа до начала прогона.
2. Файл прогона и файл выпуска — или файл сбоя — агент коммитит в свою ветку `claude/vypusk-…` и
   открывает заявку на слияние.
3. Публикатор запускается открытием заявки. Код заявки он не исполняет и файлу прогона агента не
   верит: берёт из заявки только файл выпуска (или сбоя) как данные, проверяет заявку, слот и файлы,
   сам собирает кандидатов (`sbor --konec-iz-zayavki`) за то же окно — конец периода — момент открытия
   заявки. На слот — одна публикация или одна строка сбоя: заявку, открытую вне окна своего слота (от
   09:00, 17:00 или 01:00 по Бангкоку до плюс 40 минут) или по уже обработанному слоту, публикатор
   закрывает молча — код 3, в канал ничего. Пункт выпуска, чьей ссылки нет в его сборе, отбрасывается;
   так же — пункт, чей адрес уже выходил (кроме крупной с пометкой `⭐ набирает обороты`), пункт с адресом,
   доменом или `@упоминанием` в заголовке, абзаце или имени источника (Telegram сделал бы их ссылкой)
   и пункт, чьё имя источника — не того кандидата сбора; отброшено всё — выпуск пустой и в канал не
   идёт. Файл сбоя агента — ровно одна из фраз `сбор упал`, `не ответил ни один источник`,
   `проверка выпуска не прошла`; в строку сбоя идёт фраза из кода, иная причина — нарушение схемы.
   Затем публикатор шлёт очищенный выпуск ботом, строку `не ответили` — из своего
   сбора, коммитит состояние в основную ветку ключом развёртывания, на новом состоянии собирает файл
   issue для следующего выпуска (`sbor-issue`) и коммитит его отдельно (провал этого шага — ошибка в
   логе, в канал ничего) и закрывает заявку без слияния, с итогом комментарием. Свой сбор не удался или своя заявка не прошла проверку — строка сбоя
   `sboj --slot-iz-zayavki`: слот заявки отмечен обработанным, период не сдвигается, состояние
   коммитится так же.
4. Сторож по расписанию — 09:40, 17:40, 01:40 по Бангкоку: слот не обработан и заявки агента, открытой
   в окне слота, нет — строка `выпуск <слот> не собран: заявка агента не пришла`.

Токена бота у агента нет: он только в секретах environment `publikaciya`, который получают лишь
запуски из основной ветки. Основная ветка закрыта ruleset'ом для push всем, кроме двух ключей
развёртывания: публикатора (состояние и файл issue) и окна (правки кода с компьютера владельца).

## Команды

| Команда | Кто зовёт | Что делает |
|---|---|---|
| `python3 -m newsai sbor` | агент | кандидаты за окно охвата и список не ответивших — в файл прогона |
| `python3 -m newsai sbor --konec-iz-zayavki <event.json>` | публикатор | тот же сбор, конец периода — открытие заявки (`pull_request.created_at`); коды: 2 — нет времени открытия, 4 — не ответил ни один источник |
| `python3 -m newsai sbor-issue` | публикатор, сборщик issue | поиск issue GitHub Claude Code — в файл issue; код 0 — файл записан; запрос к API не прошёл хоть раз или поиск пуст и после повтора без токена — код 2, прежний файл не тронут; в выводе — сколько дал поиск, сколько с ответом команды, начало поиска, был ли повтор без токена |
| `python3 -m newsai tekst <url>` | агент | текст страницы без разметки, до 20 000 знаков; только http/https на публичные адреса |
| `python3 -m newsai proverit` | агент | самопроверка файла выпуска или сбоя против своего файла прогона и состояния; ничего не отправляет; нарушения — по строке, код 1 |
| `python3 -m newsai proverit --zayavka <event.json> --fayly <список>` | публикатор | до сбора: заявка, слот, файлы, схема, длина, свежесть по открытию заявки; чужая заявка, заявка вне окна своего слота или по обработанному слоту — код 3 (закрыть без публикации, в канал ничего), нарушение своей — код 1 |
| `python3 -m newsai proverit --zayavka <event.json> --fayly <список> --progon <сбор публикатора> --vyhod <файл>` | публикатор | то же плюс сверка со своим сбором: пункты без ссылки в сборе, с уже выходившим адресом (кроме крупной с `oboroty`), с адресом в тексте или чужим именем источника отбрасываются, очищенный выпуск — в `--vyhod`, отброшенное — строками вывода |
| `python3 -m newsai opublikovat [--suhoj]` | публикатор | файл выпуска → сообщения в канал, файл сбоя → строка сбоя; затем состояние; на обрыв отправки сам шлёт одну строку сбоя; `--suhoj` печатает запросы к Bot API вместо отправки |
| `python3 -m newsai sboj --prichina-iz <файл>` | сторож | сообщение `выпуск <слот> не собран: <причина>`; причина — первая строка файла |
| `python3 -m newsai sboj --prichina-iz <файл> --slot-iz-zayavki <event.json>` | публикатор | то же по своей заявке: слот её открытия — в строку и в `posledniy_slot` состояния, период не сдвигается; вторая заявка того же слота закроется молча |
| `python3 -m newsai nesohraneno` | публикатор | сообщение `состояние не сохранено — следующий выпуск может повторить новости` |
| `python3 -m newsai storozh --zayavki <файл>` | сторож | слот не обработан публикатором и в списке заявок (ответ REST GitHub) нет заявки агента, открытой в окне слота — сообщение `выпуск <слот> не собран: заявка агента не пришла` |

Пути файлов данных можно подменить переменными окружения `NEWSAI_PROGON`, `NEWSAI_VYPUSK`,
`NEWSAI_SBOJ`, `NEWSAI_SOSTOYANIE` — так публикатор держит свой сбор и очищенный выпуск в папке
раннера; путь файла issue — `NEWSAI_ISSUE` (для тестов и проб).

Тесты: `python3 -m unittest discover -s tests -q` (на Windows — `py -3 -m unittest discover -s tests -q`).

## Живой выпуск с компьютера

Те же команды через `py -3`: `sbor`, отбор по `agent/SKILL.md`, `proverit`, затем `opublikovat`.
Токен бота — из файла секретов проекта. Обрыв отправки — `opublikovat` сам шлёт одну строку сбоя,
второй не нужно. После выпуска коммитится только `dannye/sostoyanie.json`; файлы прогона, выпуска и
сбоя в основную ветку не идут. Порядок — `agent/SKILL.md`, раздел «Живой выпуск с компьютера окна».

## Файлы

- `newsai/` — пакет; `tests/` — тесты на записанных ответах источников.
- `istochniki.json` — источники с фильтрами, 30 аккаунтов X, логины команды Claude Code.
- `agent/SKILL.md` — инструкция агента облачной задачи: отбор, текст, заявка;
  `agent/prompt-zadachi.md` — промпт задачи.
- `dannye/sostoyanie.json` — состояние выпусков: период, увиденное, вышедшее за 14 дней; пишет только
  публикатор, лежит в основной ветке.
- `dannye/issue.json` — файл issue: когда собран, начало поиска, issue с ответом команды; пишет только
  `sbor-issue` — у публикатора после заявки и у сборщика issue, лежит в основной ветке; читает только
  `sbor` агента, когда запрос к API не прошёл.
- `dannye/progon.json`, `dannye/vypusk.json`, `dannye/sboj.json` — файлы прогона, выпуска и сбоя
  агента; лежат только в ветке его заявки.
- `.github/workflows/publikaciya.yml` — публикатор; `.github/workflows/storozh.yml` — сторож;
  `.github/workflows/sbor-issue.yml` — сборщик issue.
- Секреты: локально — файл секретов проекта, перечень переменных — `.env.example`; в GitHub —
  environment `publikaciya`: `TELEGRAM_BOT_TOKEN` (только публикатор и сторож) и `NEWSAI_DEPLOY_KEY`
  (публикатор и сборщик issue); в среде облака переменных нет.
